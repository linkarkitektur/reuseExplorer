# Solid-model JSON and the solid-model benchmark

One document describes a typed building model: storeys, walls with a
measured thickness, spaces with polygons, openings in walls. It is written
either as JSON or as YAML (picked by file extension: `.yaml` / `.yml` is
YAML, anything else JSON) -- the two are the same document, lossless with
each other and with the `core::SolidModel` records (reusex-yf4.1); YAML is
the human-friendly front end for hand-authoring a reference, JSON the
machine-written form the pipeline itself produces. The same document, in
either form, holds both sides of the benchmark:

- a **reference plan**, authored by a person or an agent, or converted from
  another tool;
- a **detected model**, the pipeline's own output (`io::load_solid_model`
  reads it from the project's solid-model tables; a kind whose table does not
  exist is not provided).

`rux analyze solid --reference plan.json` (or `plan.yaml`) compares the two,
and `scripts/bench-solid.sh` runs that over a manifest of fixtures.

| What | Where |
|---|---|
| Records (PODs) | `libs/reusex/include/core/solid_model.hpp` (`core::SolidModel`, `WallRecord`, ...) |
| JSON reader / writer | `libs/reusex/include/io/solid_model_json.hpp` (`solid_model_from_json`, `solid_model_to_json`, `load_solid_model`) |
| YAML reader / writer | same header (`solid_model_from_yaml`, `solid_model_to_yaml`); converts YAML <-> `nlohmann::json`, then shares the JSON reader's one validator |
| Extension dispatch | `solid_model_from_file` / `solid_model_to_file`: `.yaml`/`.yml` (case-insensitive) is YAML, everything else JSON |
| JSON Schema | [`solid-model-reference.schema.json`](solid-model-reference.schema.json) (describes the logical document; a YAML file follows the same schema read through the YAML front end) |
| Metrics | `libs/reusex/include/reconstruction/solid_metrics.hpp` (`compare_solid_models`, `fit_report`) |
| CLI | `rux analyze solid` (`apps/rux/src/analyze/solid.cpp`), `rux render --plan`, `rux edit plan --import`/`--export` -- every one of these takes either extension |
| Bench | `scripts/bench-solid.sh`, `scripts/bench-solid.manifest`, `scripts/bench-solid-compare.py` |
| Fixtures | `tests/fixtures/solid_model/`: hand-written synthetic plans (`*.json`), and references authored on our own scans as hand-written, commented YAML (`newoffice.plan.yaml`, a DRAFT) -- never round-tripped through a writer, which would drop the comments |
| Authoring | [`docs/guides/solid-model-reference-authoring.md`](../guides/solid-model-reference-authoring.md) (`rux edit plan`, `rux render --plan`) |

## No ground truth

Nothing the project has is trusted ground truth (decision D5, reusex-z1v.1.5):
NewOffice's components and `export.3dm` were generated by this library. A
reference plan is a **benchmark target** that a person or agent authored and
checked visually against the scan; a converted third-party model is a
**baseline row**, scored against the same reference, never a reference
itself. S3DIS may be used locally for benchmarking, but no file derived from
it is ever committed (`tests/fixtures/solid_model/` holds hand-written
synthetic plans and references authored on our own scans).

## Document

```json
{
  "model_version": 1,
  "units": "m",
  "name": "two_rooms (synthetic reference)",
  "storeys": [{"idx": 0, "name": "Ground", "z_floor": 0.0, "z_ceiling": 2.6}],
  "walls": [
    {"guid": "w1", "storey": 0, "axis": [[0, 0], [8, 0]], "height": 2.6,
     "thickness": 0.3, "is_external": true}
  ],
  "spaces": [
    {"guid": "s1", "storey": 0, "name": "Kitchen",
     "polygon": {"outer": [[0.15, 0.15], [3.95, 0.15], [3.95, 4.85], [0.15, 4.85]]}}
  ],
  "openings": [
    {"guid": "o1", "wall": "w1", "kind": "door",
     "s_start": 1.0, "s_end": 2.0, "z_sill": 0.0, "z_head": 2.1}
  ]
}
```

A complete example is `tests/fixtures/solid_model/two_rooms.plan.json`.

The same document, as YAML (comments and all -- `rux edit plan --import` and
`rux analyze solid --reference` read this unchanged):

```yaml
model_version: 1
units: m
name: two_rooms (synthetic reference)
storeys:
  - idx: 0
    name: Ground
    z_floor: 0.0
    z_ceiling: 2.6
walls:
  - guid: w1
    storey: 0
    axis: [[0, 0], [8, 0]]
    height: 2.6
    thickness: 0.3
    is_external: true   # a real boolean, not the string "true"
spaces:
  - guid: s1
    storey: 0
    name: Kitchen
    polygon:
      outer: [[0.15, 0.15], [3.95, 0.15], [3.95, 4.85], [0.15, 4.85]]
openings:
  - guid: o1
    wall: w1
    kind: door
    s_start: 1.0
    s_end: 2.0
    z_sill: 0.0
    z_head: 2.1
```

Reading converts the parsed YAML tree to a `nlohmann::json` value first, then
hands it to the exact same strict reader the JSON form uses, so an invalid
element throws the identical `std::invalid_argument` either way (e.g.
`walls[0] (guid 'w1'): 'thickness' must be a number`, whether the bad value
came from `"thick"` in JSON or `"thick"` in YAML). A plain (unquoted) scalar
is typed the way this reader expects: `null`/`Null`/`NULL`/`~`/empty is null,
exactly `true`/`false` is a boolean, a value that parses in full as a decimal
integer or floating-point number is that number, and everything else --
including YAML's own `yes`/`on`/`True` -- is a string. Quote a value
explicitly (`"w1"`, `"123"`, `"true"`) to always read it as a string, whatever
it looks like; `solid_model_to_yaml` does this itself for any string field
that would otherwise come back as something else (a guid that happens to
read as a number, say). Comments are allowed and ignored on read; there is
nowhere in `core::SolidModel` to keep them, so a document written back out
(`rux edit plan --export`, `rux edit plan --import ... --dry-run --export`)
loses them -- the same way re-exporting is already lossy for JSON-only
presentation details like key order in a hand-edited file.

### Conventions

- **Units** are metres (`"units": "m"`, the only value accepted).
- **Frame.** Wall axes, space polygons and opening heights are in the
  storey's *level frame*: z up, storey 0's floor at z = 0. A storey's
  `level_transform` (16 numbers, 4x4 row-major) maps world to level
  coordinates; omitted means identity. Each storey has its own frame, so an
  opening's `z_sill` / `z_head` are in its host wall's storey frame. Two
  models need not share a level frame: the benchmark compares them through
  world (see *Level frames and storeys* below). An authored reference
  typically keeps world x/y and only shifts z (`level_transform` a
  translation by minus the floor's world z); the detector puts its origin on
  a storey-0 floor point (`geometry::make_level_frame`).
- **References by key, not row id.** A wall, space or opening names its
  storey by the storey's `idx`; an opening names its host wall, a join its two
  walls and a boundary its space and wall by `guid`. A `guid` is any
  non-empty string unique in the document (authored plans can use `"w1"`;
  the pipeline writes RFC 4122 v5 UUIDs).
- **Walls** are centre lines (`axis`) with a `thickness`. A wall whose
  thickness is unknown (`-1`) because only one face was seen -- an external
  wall scanned from inside -- has its `axis` **on that seen face**, not half
  a guessed thickness behind it (reusex-v8p). Reference plans and the walls
  stage both follow this: an assumed centre line would charge every
  one-sided wall the guess (about 0.1 m per endpoint). `assumed: true` means
  the thickness was defaulted rather than measured (the walls stage writes
  `-1` for a one-sided wall and keeps a defaulted thickness only for a wall
  whose two faces it saw but could not measure between); `seen_share` is the
  fraction of the wall's face with scan evidence (`-1` = not computed).
- **Spaces** have one `outer` ring and optional `holes`, in either winding.
  Every ring is simple (it does not touch or cross itself) and has non-zero
  area (at least 3 non-collinear points); every hole lies strictly inside
  the outer ring, and holes neither overlap nor touch each other. Rings are
  stored open: a ring whose last point repeats its first (GeoJSON style) is
  accepted and the repeated point dropped, so it is never written back.
- **Openings** sit in their host wall's face: `s_start` < `s_end` measured
  along the host axis from its first endpoint, `z_sill` < `z_head` in the
  level frame. `kind` is `door`, `window` or `opening`.
- **Provenance** on every element: `source` (`detected`, `manual`,
  `imported`), `locked` (a re-run must not overwrite it), `confidence` (0..1,
  -1 unknown), `metadata` (any JSON value; evidence without a field yet). In
  a record, `metadata` is that value as JSON text; the writer rejects a
  record whose `metadata` is not JSON text.
- **Numbers** are finite; integers (`idx`, `storey`, `face_points`,
  `axis_family`, ...) fit a 32-bit `int`.
- **Absent vs empty.** An element array that is *absent* means "this model
  says nothing about that kind"; *present and empty* (`"walls": []`) means
  "this model has none". The benchmark reports the first as n/a and scores
  the second as a miss. `core::SolidModel::provided` carries the distinction
  in memory.

### Strictness

`io::solid_model_from_json` rejects, with an `std::invalid_argument` naming
the element (`walls[2] (guid 'w3'): ...`): text that is not JSON (including
a number that overflows a double), an unknown key (a typo must not silently
become a default), a wrong type, a non-finite number, an integer outside
`int`, a missing `model_version` or a version other than 1, a zero-length
wall axis, a space polygon that breaks the ring and hole rules above, an
opening with `s_end <= s_start` or `z_head <= z_sill`, a reference to a wall,
space or storey the document does not contain, and a duplicate `guid` or
storey `idx`.

`solid_model_to_json` writes keys in a fixed order and every field of every
element, so `JSON -> records -> JSON` is a fixed point (tested in
`tests/unit/io/test_solid_model_json.cpp`).

### Versioning

`model_version` is bumped on any change a version-1 reader would
misinterpret (a renamed or re-meant field). Adding an optional field is also
a bump, because the reader is strict about unknown keys. The reader accepts
exactly `io::kSolidModelJsonVersion`.

## Metrics

`reconstruction/solid_metrics.hpp`, `compare_solid_models(detected,
reference, options)`. Every metric is `null` when either model does not
provide the element kind it needs.

**Level frames and storeys.** Each detected wall, space and opening is
taken out of its storey's level frame (the inverse of `level_transform`) and
into the level frame of the reference storey it is compared with, so the
two models meet in world whatever level frames they were written in. Wall
axes are mapped at the wall's mid-height, space polygons at the space's
`z_floor`, and an opening's ends at its mid-height and then measured along
the mapped host axis; its sill and head are mapped above its centre. For
frames that share the vertical (any yaw and translation) this is exact;
a small tilt between the two verticals moves plan positions by roughly
height x tilt. A `level_transform` that is singular or not finite is
rejected (`std::invalid_argument`).

When both models list `storeys`, a detected storey corresponds to the
reference storey whose floor (its `z_floor` taken to world) is nearest in
world z, within `storey_match_dist_m` (1.0 m), one-to-one, closest first:
a detector numbers storeys from the lowest one it saw, which need not be
the reference's storey 0. A detected storey with no reference storey that
close is left out like an uncovered one below (a warning names the floor
heights when no detected storey matched at all). When either model lists no
storeys, storeys correspond by `idx` and the missing side's frames are
identity.

**Storey coverage.** The reference covers the storeys in its `storeys` plus
every storey one of its walls or spaces stands on. Detected walls, spaces and
openings (by their host wall's storey) on a storey that corresponds to no
covered reference storey are left out of
every metric, so a reference that models only the ground floor does not
charge a multi-storey detection false positives or extra rooms; the number
left out is `counts.detected_outside_reference`. A reference that names no
storey at all (no storeys, walls or spaces) covers everything.

| Metric | Definition | Better |
|---|---|---|
| `room_count_error` | detected spaces - reference spaces (signed) | 0 |
| `room_iou_mean` | mean over reference spaces of the 2D IoU with the detected space matched to it; unmatched = 0 | higher |
| `wall_recall` / `wall_precision` | matched / reference walls, matched / detected walls | higher |
| `wall_position_rms_m` | RMS of matched detected walls' endpoint distances to the reference axis line; face to face when exactly one of the pair has measured faces (see Matching) | lower |
| `wall_thickness_err_mean_m` / `_p95_m` | \|detected - reference\| thickness over matched walls whose thickness is known (> 0) and measured (`assumed` false) on both sides; mean and nearest-rank P95. Pairs left out for `assumed` are counted in `counts.thickness_assumed_excluded`, scored pairs in `counts.thickness_pairs` | lower |
| `opening_recall` / `opening_precision` | matched / reference, matched / detected openings | higher |
| `opening_iou_mean` | mean over reference openings of the IoU with the detected opening paired one-to-one (greedy by IoU, any overlap, no `opening_match_iou` threshold); 0 for an unpaired one. How close the misses came | higher |
| `fit_mean_m` | mean distance of the scan cloud's points to the solid mesh | lower |
| `fit_within_share` | share of those points within `fit_within_m` (2 cm) | higher |
| `mesh_unsupported_share` | share of the solid mesh's area with no scan point within `support_dist_m` (0.25 m): the reverse direction of the fit, which sees surfaces the scan does not show (fake walls between over-split rooms). `mesh_area_m2` is the area it is a share of, `counts.support_samples` the samples tested | lower |
| `seen_share_mean` | mean `seen_share` of detected walls that report one | higher |
| `assumed_share` | share of detected walls with `assumed: true`. The flag has no "unknown" state, so a detector that never sets it reports 0 | lower |

Matching is one-to-one and greedy, best score first, ties by index, so a
report is deterministic (STANDARDS §6):

- **Walls** on the same storey match when their axes differ by at most
  `wall_match_angle_deg` (10°, undirected), the detected axis' midpoint is
  within `wall_match_dist_m` (0.5 m) of the reference axis line, and the two
  extents projected on the reference axis overlap by at least
  `wall_match_min_overlap` (0.5) of their union (a 1D IoU), so a short
  fragment lying on the line cannot take the full wall's place. Closest
  midpoint first. Distances are face to face when the two walls follow
  different conventions: when exactly one of them has known faces
  (thickness > 0 and not `assumed`), the other's axis -- a seen face, or a
  defaulted guess -- is measured to the nearer of those two faces; otherwise
  axis to axis. A one-sided detected wall on the inner face of a measured
  reference wall therefore scores 0, as does a measured detected wall whose
  inner face lies on a one-sided reference axis.
- **Spaces** on the same storey: exact 2D IoU (CGAL boolean set operations
  on polygons with holes), highest first.
- **Openings** on the same storey (their host walls' storeys): the detected
  opening is placed in plan through its host wall (after the level-frame
  mapping above), then re-expressed in the reference opening's host-wall coordinates (s
  along that axis, z); a match needs near-parallel host walls, the detected
  opening within `wall_match_dist_m` of the reference wall line, and a face
  IoU of at least `opening_match_iou` (0.5). Opening kind is not compared.
- **Fit** (`fit_report`): point-to-triangle distance through a CGAL AABB tree
  over the mesh's faces. Support: every triangle is sampled about once per
  `support_spacing_m`² (5 cm) of its area at a fixed R2 low-discrepancy
  pattern; a sample is unsupported when no scan point lies within
  `support_dist_m` (a hash grid over the cloud).

`SolidModelReport::to_json()` adds `fit_source` (the project, cloud and mesh
the fit came from, `null` when there is no fit) and a `counts` object
(reference, detected and matched walls / spaces / openings, fit points,
thickness pairs, elements outside the reference's storeys) behind the
ratios.

## `rux analyze solid`

```bash
rux -p scan.rux analyze solid --reference plan.json            # summary table
rux -p scan.rux analyze solid --reference plan.json --json -o report.json
rux analyze solid --reference plan.json --model baseline.json --json
```

The detected model is `io::load_solid_model(project)`, or `--model` for a
model file (a baseline). The fit metrics read `--cloud` (default `cloud`)
and `--mesh` (default `mesh`) from the project when both exist; with
`--model` they are computed only when `--cloud` or `--mesh` is passed
explicitly, since they measure the project's mesh, not the model file. A fit
that cannot be computed (a mesh without a usable triangle, a cloud without a
finite point) leaves the fit metrics n/a with a warning; the rest of the
report is still written. Each block of n/a metrics is explained by a
warning. Tolerances: `--wall-angle`, `--wall-dist`, `--wall-overlap`,
`--opening-iou`, `--fit-within`, `--support-dist` (defaults from
`SolidMetricsOptions`).

Exit status: 0 on success; 3 (`INVALID_ARGUMENT`) for an invalid reference,
model file or model; 2 (`IO`) when the report cannot be written; 1 for any
other failure.

## `scripts/bench-solid.sh`

Runs every row of `scripts/bench-solid.manifest` and writes one JSON report,
`bench-results/bench-solid-<stamp>-<sha>.json`:

```
# name           kind      reference                                     model                                       project   stages
two_rooms_synth  synthetic tests/fixtures/solid_model/two_rooms.plan.json tests/fixtures/solid_model/two_rooms.detected.json -   -
```

- `model` is a solid-model JSON scored with `--model`, or `-` to score the
  project's own model.
- `name` must be unique in the manifest (the comparison keys rows by it).
- `project` is a `.rux`; it is **copied** to a scratch directory before
  anything runs (opening a project can migrate it), together with its
  `-wal`/`-shm` files so un-checkpointed changes are not lost; the source is
  never opened. Paths may use
  `$VARIABLES`; a row whose variable is unset or whose files are missing is
  reported as skipped, so local-only rows (`kind` `local`, e.g. S3DIS via
  `$REUSEX_S3DIS_DIR`) cost nothing elsewhere.
- `stages` is a comma-separated list of `rux create` subcommands run on the
  copy first, or `-`.
- `kind` labels the row: `synthetic`, `fixture`, `baseline` (a third-party
  model scored as a row, never a reference) or `local`.

Compare two reports with `scripts/bench-solid-compare.py baseline.json
candidate.json [--threshold 5]`: per row and metric it prints both values and
the change, knows which direction is better for each metric, and exits 1 when
a metric got worse by more than `--threshold` percent, went from a number to
n/a, a row that ran in the baseline failed in the candidate, or no row could
be compared at all.
